# Codebase graph

Harbormaster carries a queryable code knowledge graph, built with
[graphify](https://pypi.org/project/graphifyy/) (tree-sitter over the AST, no LLM,
no network). It answers "what depends on this?", "how do A and B connect?" and
"what is X?" in a few hundred tokens with file:line citations, where grepping the
same answer costs thousands of tokens of raw source. Agents working in this repo
should query the graph before opening files — see the `graphify` section at the
top of `CLAUDE.md`.

## Build and query

```bash
uv tool install graphifyy        # once per machine
graphify update .                # rebuild the graph (AST only, ~10s, offline)
graphify explain "<name>"        # what a class/function/module is and connects to
graphify path "<A>" "<B>"        # shortest relationship between two symbols
graphify affected "<name>" --depth 2   # reverse blast radius before changing a symbol
```

`graphify update .` is safe to run any time — it re-extracts and rebuilds
`graphify-out/graph.json` from the current tree in seconds. Run it after making
code changes so `affected`/`path`/`explain` stay truthful.

## Three real queries

### 1. `graphify explain "TieredResolver"` — the mapping ladder's core class

`TieredResolver` (`python/src/inspector/mapping/resolver.py:45`) is the
three-tier field-mapping escalation engine described in the README. Plain-name
`explain` surfaced 31 connections (truncated below); the class fans out to every
tier (`Tier1Mapper`, `Tier2Matcher`, `MappingAdjudicator`), the cache
(`TemplateCache`, `InMemoryCache`), and is used by `Inspector`:

```
Node: TieredResolver
  Source: python/src/inspector/mapping/resolver.py L45
  Degree: 31
  --> ParsedTable [uses]        --> Mapping [uses]           --> AdjudicationRequest [uses]
  <-- Inspector [uses]          --> InMemoryCache [uses]      --> Tier2Matcher [uses]
  <-- Classification [uses]     --> Tier1Mapper [uses]        --> TemplateCache [uses]
  --> MappingAdjudicator [uses] <-- Path [uses]                <-- CountingAdjudicator [uses]
  ... and 11 more
```

### 2. `graphify path "scanner.go" "audit.go"` — ingress to the audit chain

Shortest path from the file-arrival ingress (`go/internal/arrival/scanner.go`) to
the tamper-evident audit store (`go/internal/audit/audit.go`), 4 hops:

```
Scanner --method--> .Scan() --calls (INFERRED)--> .Append() --references--> Entry <--contains-- audit.go
```

The CLI flagged this source match **AMBIGUOUS**: `warning: source match was
ambiguous (top score 5803.79, runner-up 5803.79)` — two nodes named `Scanner`
tie on relevance score, so a plain-name query can silently pick either one. When
a query matters, resolve the exact node ID first with `graphify explain`, then
pass that ID instead of the bare name (see the affected query below for why).

### 3. `graphify affected "harbormaster.proto" --depth 2` — the Protobuf contract

```
No unique node match for harbormaster.proto
```

This is the one thing worth flagging plainly: the plain name resolves
ambiguously (two nodes now reference `proto/harbormaster/v1/harbormaster.proto`
by that string — one from `docs/SHOWCASE.md`, one from this doc), and even with
a unique match `affected` would have little to traverse. `.proto` files are not
tree-sitter code nodes here, and `.graphifyignore` deliberately excludes the
generated bindings (`go/gen/`, `python/src/harbormaster/v1/`) that actually
carry the contract's usage edges (per the codebase-graph skill: generated
output does not belong in the graph). The graph therefore cannot trace
protobuf-contract impact across the Go/Python boundary — use
`go/internal/contract/roundtrip_test.go` and
`python/tests/test_contract_roundtrip.py` (the ADR-003 cross-language contract
tests) for that instead. `affected` does work well on hand-written symbols: for
example `graphify affected "mapping_resolver_tieredresolver" --depth 2` (using
the exact ID from `explain`, not the ambiguous plain name `TieredResolver`)
returns real call sites across `python/src/inspector/main.py`,
`bench/onboard.py`, and three test files.

## Counts and build

- 2377 nodes, 4996 edges, 154 communities (183 files)
- Extraction: AST only, no LLM, no network
- Build time: ~9 seconds, fully offline (`graphify update .`, no API key)

## What `.graphifyignore` excludes

- `python/.venv/` — the Python virtual environment (~400 MB)
- `go/gen/` and `python/src/harbormaster/v1/` — generated protobuf bindings
  (`*.pb.go`, `*_pb2.py`); regenerated by `make proto` / `buf generate`
- `graphify-out/` — the tool's own build output
- Python/pytest/mypy/ruff caches (`__pycache__/`, `.mypy_cache/`, `.ruff_cache/`,
  `.pytest_cache/`)

`graphify-out/graph.json`, `graph.html`, `cache/` and friends are also excluded
from git (see `.gitignore`) — only `graphify-out/GRAPH_REPORT.md` is committed.
Rebuild the rest locally with `graphify update .` in 5–30 seconds.

## The agent-facing skill and hooks

`graphify install --project --platform claude` installed
`.claude/skills/graphify/` (committed) and wrote the graphify section at the
top of `CLAUDE.md` (committed) so any Claude Code session in this repo knows to
query the graph before reading files. It also offered PreToolUse hooks in
`.claude/settings.json` that intercept Read/Grep/Bash-search calls with a
reminder to query first; those hooks were **not** committed — they are a local,
per-developer opt-in. Run `graphify install --project --platform claude` again
yourself if you want them.

## Shipyard integration

In the Shipyard lifecycle, Implementers query the graph before opening files
for a task pack, and Verifiers run `graphify affected` on every symbol a diff
touches to confirm nothing outside the pack's declared scope moved.
